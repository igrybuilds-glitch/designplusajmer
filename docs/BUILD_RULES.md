# Design Plus — Build Rules & Permanent Engineering Directives

## 1. Scope & Execution Principles
* **Smallest Sufficient Change**: Make the smallest change that fully satisfies the task.
* **No Unrelated Rewrites**: Do not rewrite or refactor unrelated files or modules.
* **Preserve Working Functionality**: Protect existing working features, routes, schemas, and UI components.

## 2. Business Fact & Integrity Rules
* **Never Invent Business Facts**: All company information must strictly align with verified business facts.
* **No Fictional Entities**: Do not invent projects, clients, testimonials, awards, reviews, ratings, statistics, or Google ranking claims.
* **Reference Ethics**: SC Architects is a strategic structural benchmark only; never copy its text, images, code, branding, or exact layout.
* **Concept Transparency**: All conceptual architectural studies must be explicitly labeled as `CONCEPT PROJECT` or `DESIGN STUDY`.

## 3. Quality & Verification Standards
* **Continuous Validation**: After every implementation, run the relevant validation/build (`npm run lint`, `npm run build`, `npm run seo:audit`).
* **Fix Before Finishing**: Identify and fix any compiler, linter, or SEO errors before concluding a task.
* **No Unverified Completion**: Never claim completion without active tool-based verification.
